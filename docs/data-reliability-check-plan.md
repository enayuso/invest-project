# 데이터 신뢰성 점검 루프 계획

> **상태(2026-10-02 문서 정리 메모)**: **보류 중인 설계 문서**(폐기·완료 표시가 아니다). 단타(스캘핑) 백테스트 인프라 일부(`app/backtest/scalping_harness.py`, `fill_simulation.py`, `minute_candles.py`, `scripts/*minute*`)는 이 문서를 근거로 코드가 존재하지만, 운영 시스템은 스윙 전략이며 단타는 "살아있는 신호 없음"으로 보류돼 있다(`handoff/knowledge/open-issues.md` D절). 코드 주석이 이 경로를 인용하므로 파일은 이동하지 않았다.

단타 백테스트 인프라(Phase 0~3, `docs/scalping-backtest-infra-plan.md`)를 만들면서 KIS
과거 분봉 응답 자체에 원인 불명의 데이터 갭(000660.KS 2026-07-13, 13:28→13:58 30분 누락)을
발견했다. 이게 얼마나 자주/어떤 패턴으로 발생하는지 모르는 채로 백테스트 결과를 계속
신뢰하는 건 위험하므로, 이를 체계적으로 스캔하는 반복 점검 루프를 만든다. 아직 착수 전이며,
이 문서는 계획만 담는다(코드 미작성).

## 1. 목표

여러 종목·여러 날짜의 분봉 데이터를 훑어서 "정상적인 갭(장 마감 동시호가 구간)"과
"원인 불명의 갭"을 구분해 집계하고, 후자가 얼마나 흔한지에 대한 근거를 쌓는다. 이 근거를
바탕으로 "지금 백테스트 결과를 어느 정도까지 신뢰할 수 있는가"를 판단한다.

## 2. 정상 갭 vs 이상 갭 기준

- **정상(제외 대상)**: `15:19~15:30`(장 마감 동시호가/단일가 매매 구간) — 이미 005930.KS
  검증에서 이 구간만 비는 게 정상임을 확인함.
- **이상(플래그 대상)**: 그 외 시간대(09:00~15:19)에서 1분 이상 끊기는 모든 구간. 길이별로
  분류해서 기록:
  - 짧은 갭(2~5분): 실제로 그 순간 거래가 드물었을 가능성도 있어 즉시 "이상"으로 단정하지
    않음, 다만 종목의 평소 유동성 대비 비정상적으로 잦으면 플래그
  - 긴 갭(10분 이상): 000660 사례처럼 명백히 의심스러운 수준 — 우선순위 높게 기록

## 3. 스캔 범위

1차는 이미 캐시된 데이터(005930.KS, 000660.KS 일부 날짜)로 스캐너 자체를 검증하고,
이후 범위를 넓힌다:
- 워치리스트 전체 종목(`settings.watchlist`)
- 최근 N영업일(우선 2주치 정도로 시작 — 과도한 KIS 호출 방지, 필요하면 확대)

## 4. 구현 계획

- **신규 스크립트** `scripts/scan_minute_data_gaps.py` — `app/backtest/minute_candles.py`의
  `fetch_and_cache_minute_day`/`get_cached_minute_day`를 그대로 재사용(새 데이터 조회
  로직 안 만듦). 각 (ticker, trade_date) 조합에 대해:
  1. 분봉을 시간순 정렬
  2. 연속되지 않는 지점(1분 초과 간격)을 전부 찾음
  3. `15:19~15:30` 구간과 겹치는 갭은 제외
  4. 나머지는 길이·시각과 함께 기록
- 이미 캐시에 있으면 그대로 쓰고, 없으면 KIS에서 새로 받아옴(기존 캐시 정책 그대로 재사용,
  스캐너 전용 로직 없음).
- 출력은 종목별/날짜별 갭 목록 + 요약 통계(종목당 이상 갭 발생 빈도, 갭 길이 분포)를
  콘솔에 표 형태로 출력. 별도 저장소(DB 테이블)까지는 1차 범위에 넣지 않음 — 우선 사람이
  눈으로 보고 판단하는 수준으로 시작.

## 5. 판단 기준 (결과 해석)

- 이상 갭이 극히 드물게(예: 전체 스캔의 1% 미만) 발견되면: 지금 백테스트 결과는 대체로
  신뢰 가능, 개별 사례만 주의
- 이상 갭이 특정 종목/시간대에 반복적으로 몰리면: 그 패턴 자체가 원인 규명의 단서가 될 수
  있음(예: 특정 유동성 낮은 종목군에서만 발생하는지, 특정 시간대에 몰리는지)
- 이상 갭이 광범위하게 발견되면: 모의계좌 분봉 데이터 자체의 신뢰성을 재검토해야 하고,
  Phase 2 슬리피지 모델의 `gap_inflated` 처리 방식도 다시 봐야 함

## 6. 반복 주기 (아직 결정 필요)

두 가지 방식 중 선택 필요:
- **(a) 필요할 때 수동 실행** — 백테스트 결과를 신뢰해야 하는 시점마다 사람이 직접 스캔
  스크립트를 돌림
- **(b) 백필 시 자동 동반 실행** — `scripts/backfill_minute_candles.py`가 새 데이터를
  받을 때마다 자동으로 갭 리포트도 같이 출력하도록 통합

1차는 (a)로 시작해서 별도 스크립트로 두고, 결과가 쌓이면 (b)로 통합할지 판단하는 게
안전하다고 본다 — 아직 "이상 갭"의 실제 발생 패턴 자체를 모르는 상태라, 자동화부터
하면 무엇을 자동화하는지도 불분명하기 때문.

## 7. 다음 결정 필요 사항

1. 스캔 범위를 워치리스트 전체로 바로 넓힐지, 이미 캐시된 2개 종목으로 먼저 스캐너 로직만
   검증할지
2. "짧은 갭(2~5분)"도 기록에 남길지, 아니면 처음부터 10분 이상만 볼지
3. 반복 주기를 수동/자동 중 어느 쪽으로 시작할지 (5절 참고, 수동 권장)
