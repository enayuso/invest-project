## 1. 이 문서의 용도

이 문서는 invest-project 프로젝트가 "지금 어느 단계에 있고, 무엇이 왜 결정됐는지"를 기록하는 단일 소스오브트루스다. 특정 AI 도구(Claude Code)의 개인 메모리에만 있던 내용을 저장소로 옮긴 것으로, Claude·ChatGPT·Cursor 등 어떤 AI 도구를 쓰든, 혹은 사람이 직접 보든 동일하게 참조할 수 있어야 한다.

**목적은 재논의 방지다.** 이미 근거를 들어 확정한 결정(예: 국내종목 Sentiment Analyst 스킵, X 연동 안 함, 완전자동 보류 조건)을 새 세션이 처음부터 다시 검토하지 않도록 한다. 결정을 뒤집으려면 "재검토 조건"에 명시된 상황이 실제로 발생했는지부터 확인한다.

**갱신 규칙:** 결정이 바뀌거나 로드맵 단계가 진행되면, 그 변경을 만든 커밋에 이 파일의 관련 항목도 같이 갱신한다. 별도 커밋으로 미루지 않는다. 이 문서는 코드가 실제로 하는 것과 실제로 확정된 결정만 기록하며, 아직 하지 않은 일을 계획처럼 부풀려 적지 않는다.

이 문서와 함께 유지되는 나머지 3개 문서: architecture(구조), safety-and-risk(안전장치/리스크), development-conventions(개발 규칙). 60개 문서짜리 "바이블" 체계는 개인 도구 규모에 맞지 않아 기각했고(2026-07-20), 이 4개만 유지한다.

## 4. 확정된 결정 기록

### 2026-07-16 — 실전투자 기본값은 항상 모의투자, 실전은 opt-in
- **결정**: `KIS_ACCOUNT_MODE=real`은 사용자가 직접 설정해야만 활성화된다. 기본값은 항상 모의투자.
- **근거**: 사용자가 실전을 기본값으로 하자고 제안했으나, 기존 fail-safe 관례(`KIS_EXECUTION_DRY_RUN` 기본 true, dashboard host 기본 127.0.0.1)와 일관성을 위해 반대 권고, 사용자 동의.
- **재검토 조건**: 없음 — 이 원칙 자체는 재검토 대상이 아니라 지속 원칙.

### 2026-07-16 — 실주문 전송은 매번 사용자 확인 필수
- **결정**: dry-run이 아닌 실제 주문 전송은 매번 명시적으로 확인받은 후에만 진행. 한 번 승인받았다고 이후 자동 반복 실행하지 않는다.
- **근거**: 실제 자금 리스크, fail-safe 원칙 유지.
- **재검토 조건**: 없음 — 지속 원칙.

### 2026-07-16 — 실주문 재개는 보류, 명시적 지시 없이 재개하지 않음
- **결정**: 2026-07-13 실주문 검증(삼성전자 1주 시장가 매수, 체결 확인)까지는 통과했으나, 이후 자동 미러링 실주문 재개는 사용자가 명시적으로 보류를 재확인함.
- **근거**: 안전장치(킬스위치, 서킷브레이커 등)부터 강화하는 순서를 사용자가 선택함.
- **재검토 조건**: 사용자의 명시적 재개 지시.

### 2026-07-20 — 멀티브로커(토스 등) 확장 보류, KIS 안정화 우선
- **결정**: 토스증권 Open API(`developers.tossinvest.com`)가 지수 단위 개인/외국인/기관 순매수, 원/달러 환율 등 KIS에 없는 데이터를 제공함을 확인했으나, 연동은 착수하지 않는다.
- **근거**: 3단계에서 멀티브로커 구조(BrokerPort/MarketDataPort)는 이미 검증돼 있어 나중에 붙이는 비용이 낮음. 지금은 KIS 쪽 안정화(1단계 슬림화, 2단계 잔여 실주문 재개 여부)가 먼저.
- **재검토 조건**: KIS 안정화(1단계 슬림화 등) 완료 이후.

### 2026-07-20 — Sentiment Analyst는 국내(.KS) 종목에서 영구 스킵
- **결정**: 코드로 확인한 결과 reddit/stocktwits는 KRX 종목 커버리지가 구조적으로 전무. 국내 종목에 대해 Sentiment Analyst 호출을 영구 스킵한다.
- **근거**: 빈 데이터에 LLM 호출만 낭비되고, 토론 단계에서도 가중치 없이 텍스트 블록으로만 소비되어 효용이 없음. 국내 심리 신호는 이미 수급(market_analyst)과 공매도/프로그램매매(risk debate)가 대체하고 있음.
- **재검토 조건**: 네이버 종목토론실 등 국내 소스를 정식 연동할 때.

### 2026-07-20 — X(트위터) 인플루언서 계정 데이터 연동 안 함
- **결정**: (사용자 확정) X 인플루언서 계정 기반 심리 데이터 연동을 하지 않는다.
- **근거**: X API 유료화로 무료 티어가 폐지됨. 단일 계정 의견은 집단 심리가 아니라 이해상충 있는 개인 의견이며, 단일 장애점(single point of failure)이 됨.
- **재검토 조건**: 없음 — 별도 강력한 동기가 생기지 않는 한 재검토하지 않음.

### 2026-07-20 — 선물/레버리지/인버스 상품 자동매매 배제

- **근거**: 반자동/자동 경로는 사람 개입이 줄어 마진콜/청산 리스크를 감당할 수 없고, 시스템의 사이징·손절 로직 자체가 이런 상품을 위해 설계되어 있지 않음.

- **결정 내용(완료)**: 강제종료된 클라이언트의 idle-in-transaction 세션이 2시간 락을 보유해 96개 세션이 적체되는 사고 발생. 수정 사항: DB pool 축소(2/5), 실패 시 백오프(15초), 서버측 세션 타임아웃 3종 적용(`idle_in_transaction` 30초 / `statement` 2분 / `idle` 5분). SSE `/api/stream` 수명을 약 5분으로 제한해 Ctrl+C로 종료 가능하도록 함.
- **근거**: 락 적체로 인한 DB 장애 재발 방지.
- **재검토 조건**: 해당 없음(완료된 인프라 수정, 추가 사고 발생 시 타임아웃 값 재조정 검토).

### 2026-07-20 — 매수 실행 타이밍의 한계 인지 및 수용
- **결정**: 현재 시스템은 스윙/포지션(며칠~몇달) 등급 판단용으로 설계되어 있고, 30분 주기+순차 파이프라인 구조상 정밀 매수 타이밍은 불가능하다는 점을 인지하고 수용한다. 매도측은 손절 루프(규칙 기반)가 빠른 대응을 담당하지만, 매수측 빠른 실행 계층(지정가 자동 조정 등)은 아직 구현하지 않는다.
- **근거**: 지금은 판단 품질 검증(1단계)이 우선순위이며, 타이밍 개선에 리소스를 먼저 투입하는 것은 순서상 이르다고 판단.
- **재검토 조건**: 1단계(에이전트 슬림화) 트랙레코드 확보 이후, 로드맵 후보로 재논의.

### 2026-07-20 — 완전자동(FULL_AUTO) 사용 안 함 재확인
- **결정**: FULL_AUTO는 로드맵 5단계 조건(1~4단계 트랙레코드 확보)을 충족하기 전까지 사용하지 않는다. FULL_AUTO는 정의상 승인 팝업 자체가 없다(사람 확인 단계 생략이 정의). 현재 approval threshold가 off 상태인 것이 유일한 예외적 안전장치라는 점을 문서화한다.
- **근거**: 5단계 조건 미충족. 완전자동은 본인 계좌 한정이라도 트랙레코드 검증 없이 진행할 수 없음.
- **재검토 조건**: 1~4단계 트랙레코드가 기준을 통과할 때.

### 2026-07-20 — 문서화 방침: 4개 문서 체계로 한정
- **결정**: 60개 문서짜리 "바이블" 생성 방식을 기각하고, 실코드에서 추출한 4개 문서(architecture / safety-and-risk / development-conventions / status-and-decisions)만 유지한다.
- **근거**: 개인 도구 규모에 60개 문서 체계는 유지비용이 실익을 초과함. 문서는 "코드가 실제로 하는 것"만 기록하고 상상을 배제해야 함.
- **재검토 조건**: 트레이딩 회사 설립 또는 상용화(타인 계좌를 다루는 시점)로 전환할 때 문서 체계 확장을 재검토.

### 2026-07-20 — dev 테스트 스크립트 2종 추가
- **결정 내용(완료)**: 개발용 테스트 스크립트 2개를 추가했다. `scripts/seed_test_pending_order.py`는 가짜 승인대기 주문을 만들어 승인 UI를 실데이터 없이 테스트할 수 있게 하고, `scripts/run_auto_trade_cycle_now.py`는 자동매매 사이클을 즉시 실행한다(`--force` 옵션으로 장시간 체크를 우회할 수 있으나, KIS 자체의 거래시간 제약은 우회할 수 없다).

### 2026-07-20 — 실제 해외 매수/매도 테스트 중 발견된 버그 2건 수정 (완료)
- **해외 매도 TR ID 오류**: `app/brokers/kis/overseas/order.py`의 모의투자 매도 TR을 `VTTT1006U`(실전 TR에 단순히 V만 붙인 값, 존재 안 함) → `VTTT1001U`(KIS 공식 예시 기준 정답)로 수정. 매수는 "V+실전TR"이 우연히 맞았지만 매도는 번호 자체가 다름 — 실제로 사용자 휴대폰 앱으로는 같은 포지션 매도가 되는데 대시보드에서만 "모의투자 미지원" 오류가 나서 발견함.
- **현금충분성 체크와 원화예수금 표시 분리**: `frcr_drwg_psbl_amt_1`(orderable)이 이 계좌에서 통화 무관하게 항상 0으로 응답됨(원시 응답 직접 확인, `WCRC_FRCR_DVSN_CD` 01/02 기준 전환도 응답에 영향 없음 확인됨 — 버그 아니라 KIS의 실제 응답). 실주문이 잘못 차단되는 걸 막으려고 `deposit`(신뢰 가능한 값)으로 대체하는 보정을 넣었었는데, 이걸 `fetch_overseas_present_balance` 안에 박아두는 바람에 대시보드의 "원화예수금"도 "외화예수금"과 똑같은 값을 보여주는 부작용이 생김. 보정을 `kis_bridge.insufficient_cash_block`(주문 게이트) 전용으로만 옮기고, 조회 함수 자체는 KIS 원본 값(0)을 그대로 반환하도록 분리 — 원화예수금은 정직하게 0으로 표시됨.
- **재검토 조건**: 해당 없음(둘 다 검증 완료된 버그 수정).

### 2026-07-20 — 대시보드에서 페이퍼 원장(paper ledger) 표시 전면 제거
- **결정**: `/api/portfolio`(보유종목·포트폴리오 상세)와 `/api/trades`(최근 거래)가 더 이상 로컬 paper ledger의 수량/현금으로 대체 표시하지 않는다. KIS에 실제로 없는 포지션은 `shares=0, venue=null`로만 표시.
- **근거**: paper ledger는 AI 리밸런싱을 KIS 전송 성공 여부와 무관하게 항상 기록하므로(`rebalance_to_target`의 "ledger 먼저, KIS 미러링 나중" 순서), 실제 KIS 계좌 상태와 구분 안 되는 표시가 됨 — 실사용 중 NVDA가 58주 보유로 잘못 표시되는 걸 발견해서 확정.
- **부수 효과**: `/api/trades`가 KIS 자체 주문번호(`order_no`)로 2차 정렬되도록 함께 수정 — 같은 날짜 여러 건이 최신순으로 안 쌓이던 문제도 해결.
- **재검토 조건**: 해당 없음(완료, 화면 표시 방식 자체의 변경).

아래 항목들은 아직 결정되지 않았거나, 착수하지 않기로 한 것이 아니라 순서상 뒤로 미룬 것이다. 재개 조건은 각 항목 참조.

- **실주문 재개**: 2026-07-13 검증까지 통과했으나 재개는 사용자의 명시적 지시 있을 때만.
